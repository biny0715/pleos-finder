## 1. 서비스 개요

플레오스 Finder는 가족이나 다른 차량을 그룹으로 초대하고, 상대가 허용한 범위 안에서 서로의 위치를 차량 내비와 휴대폰에서 실시간으로 보는 Pleos Connect 앱입니다. 운전자는 폰을 만지지 않고 상대 위치로 바로 길 안내를 받고, 기다리는 사람은 차가 어디쯤 오는지 폰으로 확인합니다.

여기에 **스마트 멀티 픽업**을 더합니다(1단계 [구현], 순서 추천 [개발 예정]). 운전자가 여러 명을 원하는 순서대로 골라 최종 목적지까지 한 번에 안내받고, Finder는 실제 도로 기준으로 더 빠른 순서가 있을 때만 **선택적으로 추천**합니다. 기본은 언제나 **사용자가 정한 순서**이고, 추천은 운전자가 수락할 때만 적용합니다. 기다리는 사람은 각자 **본인이 픽업될 때까지** 남은 거리·시간·예상 픽업 시각을 폰으로 봅니다.

**한 줄 소개:** 차와 사람을 잇는 '나의 찾기' — 공유한 사람끼리, 필요한 동안만.

**이름의 의미:** 플레오스 Finder는 사람을 찾고(Find People), 그룹에서 서로를 찾고(Find Each Other), 여러 명을 태울 때 더 나은 길을 찾는(Find the Best Route) 서비스입니다. 슬로건: **사람을 찾고, 최적의 길을 찾다.** 단, 길은 강요하지 않고 운전자가 정한 경로를 존중하며 더 나은 순서를 제안만 합니다.

**공모 분야:** 패밀리·동승자 케어

**계정:** 차량과 폰 모두 Pleos 계정으로 로그인해 사용합니다. Pleos 계정 정보를 외부 앱이 받아 오는 방법은 협의가 필요해, 공모전 출품본은 Finder에 로그인되어 있다고 가정하고 구현합니다.

**배경과 문제**

- 픽업할 때 "어디야?", "어디쯤 왔어?" 전화가 반복되고, 운전 중 통화는 위험합니다.
- 기존 위치 공유 앱은 폰 중심이라 운전자가 확인하려면 폰을 봐야 합니다.
- 상대 위치를 알아도 내비에 다시 검색해서 목적지를 찍어야 합니다.
- 위치를 항상 공유하는 방식은 친구나 동료 사이에서 프라이버시 부담이 큽니다.

**목표**

1. 상대 위치를 목적지로 한 번에 길 안내 시작
2. 차량과 폰 양쪽에서 서로의 위치와 도착 예정 시간 확인
3. 위치를 보여줄지는 공유하는 사람이 정함: 항상 허용 또는 필요할 때만 허용(일시적 허용)
4. 여러 명을 픽업할 때 운전자가 정한 순서를 기본으로 안내(특정 인원 먼저 픽업 고정 가능) **[구현]**, 더 빠른 순서는 선택적으로 추천 **[개발 예정]**
5. **[구현]** 픽업 대상마다 본인 차례까지의 경로상 남은 거리(km)·시간(분)·예상 픽업 시각 안내

## 2. 대상 사용자와 핵심 시나리오

연결은 가족, 친구, 그룹 세 가지입니다. 가족과 친구는 1:1 연결이라 픽업에 쓰고, 그룹은 여러 사람과 차량이 정해진 시간 동안 서로의 위치를 보는 데 씁니다. 메인 시나리오는 가족 픽업입니다.

| 패널 | 추가 대상 | 일시적 허용의 뜻 | 핵심 가치 |
| --- | --- | --- | --- |
| 가족 | 가족 구성원 (사람, 차량) | 픽업 요청이 올 때마다 수락, 픽업이 끝나면 종료 | 전화 없는 픽업, 운전 중 가족 위치 확인 |
| 친구 | 친구·직장 동료 등 가족이 아닌 사람과 그 차량 | 가족과 같음 (픽업·합류 요청 때마다 수락) | 다른 사람의 Pleos 차량이 나를 데리러 올 때 |
| 그룹 | 연락처에서 초대한 여러 사람과 차량 | 정한 시간 동안만 공유 (30분 단위로 연장) | 여행·촬영처럼 여러 차량이 함께 이동할 때 |

### 위치 공유 허용 방식

| 허용 방식 | 가족·친구 (1:1) | 그룹 |
| --- | --- | --- |
| 항상 허용 | 요청이 오면 확인 없이 바로 공유하고, 요청한 차량의 내비가 즉시 길 안내 | 그룹 구성원 모두가 내 위치를 계속 봄 |
| 일시적 허용 | "아빠에게 위치를 공유할까요?" 알림을 수락하면 공유, 픽업이 끝나면 자동 종료 | 지금부터 정한 시간 동안만 공유. 30분 단위로 + 버튼을 눌러 연장하고, 시간이 지나면 자동 종료 |
| 끄기 | 공유하지 않음 | 공유하지 않음 |

허용은 상대별(가족·친구)·그룹별로 따로 정합니다. 예를 들어 아들은 아빠에게 항상 허용, 엄마에게 일시적 허용을 줄 수 있습니다.

### 사람·차량 표시와 운전자 기준 공유

목록의 이름 옆 아이콘으로 상대에게서 무엇을 볼 수 있는지 보여 줍니다.

| 상대 | 표시 | 예 |
| --- | --- | --- |
| 폰에 플레오스 Finder를 설치한 사람 | 이름 + 사람 아이콘 | 아들 |
| Pleos 차량을 운전하고 Finder도 설치한 사람 | 이름 + 사람 + 차량 아이콘 | 엄마, 친구 김민수 |
| Pleos 차량을 운전하지만 Finder는 설치하지 않은 사람 | 이름 + 차량 아이콘 | 직장 동료 박지훈 |

- 차량 위치는 차량이 아니라 지금 운전하는 사람의 공유 설정을 따릅니다. 아빠 차를 평소에는 아빠가 운전해 아빠 그룹에 항상 공유되더라도, 엄마가 운전하는 동안에는 엄마의 설정이 적용되어 아빠 그룹에는 공유되지 않습니다.
- 운전자는 차량에 로그인한 Pleos 계정으로 정합니다. 출품본은 Pleos 계정을 받아 올 수 없어, Finder 화면 오른쪽 위 프로필에서 운전자(아빠·엄마)를 바꾸는 방식으로 시연합니다.

### 차량끼리 위치 공유

차량 아이콘이 있는 상대를 누르면 [위치 공유] 버튼이 나타납니다. 내 차와 상대 차가 정한 시간 동안 서로의 위치를 보는 기능이고, 항상 일시적입니다.

| 선택 | 동작 |
| --- | --- |
| 오늘 하루만 공유 | 오늘 밤 12시까지 서로 공유 |
| 시간 설정 | −30분 / +30분 버튼으로 30분~24시간 중 골라 그 시간만 공유 |
| 공유 중지 | 공유 중일 때 나타나며, 즉시 양쪽 공유 종료 |

- 공유 중에는 버튼이 "공유 중 ~오후 11:30"처럼 끝나는 시각을 보여 줍니다.
- 서로의 차량 위치는 내비게이션에 표시하는 것이 목표입니다. 기본 내비 지도에 외부 앱이 마커를 그리는 API가 아직 없어, 출품본은 Finder 지도에 표시하고 내비 표시는 Pleos와 협의합니다.

### 시나리오 A — 가족 픽업 (메인)

**시연 무대 (가정):** 발표 장소를 아빠의 회사로 가정합니다. 아빠가 판교 제2테크노밸리의 회사에서 퇴근하며 판교역에서 기다리는 아들을 태우고 집(판교원마을)으로 갑니다. 엄마는 판교역 북쪽 봇들마을, 친구들은 정자역·서현역 근처에 있고, 주말에는 '강릉 여행' 그룹으로 집에서 강릉 경포해변까지 함께 이동합니다. 출품 앱의 시연 데이터와 저장한 장소(우리 집, 강릉 경포해변)도 이 무대에 맞춰 두었습니다.

가족 구성: 엄마(그랜저), 아빠(아이오닉5), 아들, 딸. 두 차량은 Pleos Connect 지원 차량이고 엄마와 아빠가 각자 차량에 Pleos 계정으로 로그인해 있습니다. 아빠가 가족 그룹을 만들어 아들과 딸을 초대했고, 아들과 딸은 폰의 플레오스 Finder에 로그인해 초대를 수락하면서 아빠에게 줄 위치 공유 방식을 골랐습니다.

1. 아빠가 차량 화면의 Finder에서 아들을 고르고 '픽업 시작'을 누르거나, Gleo AI에게 "아들 데리러 가자"라고 말합니다.
2. 아들이 아빠에게 **항상 허용**을 두었다면, 확인 없이 아들 폰의 현재 위치가 내비 목적지로 설정되고 길 안내가 시작됩니다.
3. **일시적 허용**이라면 아들 폰에 "아빠가 픽업하러 가려고 해요. 위치를 공유할까요?" 알림이 옵니다. 수락하면 그때 길 안내가 시작되고, 거절하면 아빠 차량 화면에 "아들이 위치 공유를 거절했어요"가 표시됩니다.
4. 아들 폰에는 "아빠가 픽업하러 오고 있어요"와 함께 아빠 차의 위치, 남은 거리, 도착 예정 시간이 표시됩니다.
5. 아들이 자리를 옮기면 목적지가 새 위치로 갱신되어 경로가 다시 잡힙니다.
6. 차가 도착하거나 아들이 차 근처로 오면 픽업이 자동으로 완료되고 "픽업 완료" 알림이 갑니다. 일시적 허용이었다면 이때 위치 공유도 함께 끝납니다.
7. 아들이 엄마에게도 항상 허용을 두었다면, 엄마도 운전 중 자기 차량 화면에서 아들과 아빠 차의 위치를 확인합니다.

### 시나리오 A2 — 여러 명 픽업 후 최종 목적지 (스마트 멀티 픽업) [1단계 구현 · 추천은 개발 예정]

1·2·3·7·8·10번은 출품 앱에 구현해 에뮬레이터에서 확인했고, 4·5·6번(순서 추천과 수락·거절)과 9번의 경로 재계산 중 일부는 개발 예정입니다.

한 명 픽업(시나리오 A)은 그대로 두고, 2명 이상을 태우는 **별도의 멀티 픽업 모드**로 추가합니다. 한 명만 고르면 기존 단일 픽업으로 이어집니다.

1. 아빠가 정차 중 Finder에서 **엄마 → 아들 → 딸** 순서로 픽업할 사람을 고르고, 최종 목적지(예: 집)를 정합니다. 고른 순서가 **기본 경로**입니다.
2. 필요하면 **순서 고정**을 켭니다(예: "엄마를 반드시 먼저 픽업"). 고정한 순서는 추천이 절대 바꾸지 않습니다.
3. Finder가 각 사람의 위치 공유 상태를 확인합니다. 일시적 허용인 사람에게는 공유 요청을 보내고, 미승인·거절·만료 상태를 화면에 표시합니다. 위치를 받지 못한 사람은 추천 계산에 넣지 않습니다.
4. 실제 도로 기준 이동시간으로 순서를 비교해, 고정 조건을 지키면서 **더 빠른 순서와 절약 시간**을 계산합니다. 더 빠른 순서가 없거나 계산할 수 없으면 추천 없이 아빠가 고른 순서로 바로 안내합니다.
5. 더 빠른 순서가 있으면 짧은 확인 팝업으로 묻고, 지원되는 경우 Gleo AI 음성으로도 안내합니다.
   - 팝업: "현재 순서보다 **아들 → 엄마 → 딸** 순서가 약 8분 빠릅니다. 변경하시겠어요?" — 버튼 **[추천 순서로 변경] [기존 순서 유지]** (8분은 실제 계산값으로 바뀜)
   - Gleo 음성 목표: "아들을 먼저 픽업하면 약 8분 더 빠릅니다. 순서를 변경할까요?"
   - 엄마를 먼저 픽업하도록 고정했다면 엄마를 첫 번째로 둔 순서(예: 엄마 → 딸 → 아들) 안에서만 추천하고, 고정을 어기는 아들 → 엄마 → 딸은 제안하지 않습니다.
6. **[추천 순서로 변경]을 눌렀을 때만** 추천 순서를 적용합니다. **[기존 순서 유지]·무응답·음성 인식 실패는 오류가 아니라 정상 선택**이며, 엄마 → 아들 → 딸 그대로 안내합니다.
7. 확정된 순서를 차량 내비 경유지로 넘겨 길 안내를 시작합니다.
8. 아들과 딸의 폰에는 각자 **본인이 픽업될 때까지** 남은 시간(분), 경로상 남은 거리(km), 예상 픽업 시각, 진행 상태(예: "엄마 픽업 후 아들 차례")가 표시됩니다. 앞사람을 거쳐 오는 경로 기준이라 두 사람의 값은 서로 다르고, 직선거리로 표시하지 않습니다.
9. 차가 움직이거나 앞사람 픽업이 끝나면 사람마다 남은 거리·시간을 갱신합니다. 누군가 자리를 옮기거나 취소·공유 종료하면 남은 경로를 다시 계산하되, **운전자 승인 없이 순서를 바꾸지 않습니다.**
10. 마지막 사람을 태우면 최종 목적지(집)로 안내합니다.

### 시나리오 B — 차량 그룹: 친구 여행

친구들이 각자 다른 차를 타고 여행을 떠납니다. 한 명이 차량 그룹을 만들어 친구들의 차량을 초대하면, 초대받은 차량의 운전자는 차량 화면에서 수락하며 항상 허용 또는 일시적 허용을 고릅니다. 항상 허용한 차량끼리는 서로의 위치가 내비에 계속 보이고, 일시적 허용이면 '합류하러 갈게요' 같은 요청이 왔을 때 수락한 동안만 공유됩니다.

### 시나리오 C — 차량 그룹: 촬영 스태프

촬영팀은 장비 차량, 배우 차량, 스태프 차량을 하나의 차량 그룹으로 묶습니다. 촬영 기간 동안 항상 허용으로 두면 모든 차량의 위치가 서로의 내비에 보이고, 촬영 장소를 목적지로 한 번에 공유합니다. 디벨롭 단계에서는 차량 간 무전으로 이동 중 소통합니다.

### 디벨롭 단계 기능 — 차량 무전

같은 그룹의 차량과 폰끼리 무전기처럼 대화하는 기능입니다. 운전 중 주의 분산 기준과 마이크 사용 정책을 검토한 뒤 단계적으로 구현합니다.

1. **1단계 — 음성 메시지:** Gleo AI에게 "아들한테 5분 뒤 도착한다고 전해줘"라고 말하거나 화면 버튼을 누르고 말하면 글자로 바꿔 전송하고, 받는 차량은 음성 합성(TextToSpeech)으로 읽어 줍니다.
2. **2단계 — 핸들 버튼 연동:** 핸들의 특정 버튼으로 말하기를 시작합니다.
3. **3단계 — 실시간 무전:** 누르는 동안 말하고 떼면 상대에게 바로 들리는 음성 무전입니다.

## 4. Gleo AI 음성 연동

운전자는 "글레오, 아들한테 픽업 갈 건데 내비랑 아들에게 위치 공유해 줘" 한 마디로 픽업을 시작합니다. Finder는 Pleos 공식 연동 방식인 [Gleo Interface](https://document.pleos.ai/en/docs/pleos-only/app-integration-guide/guide/core-concepts)로 Gleo AI와 연결됩니다.

### 동작 흐름

1. 운전자가 Gleo AI에게 픽업을 요청합니다.
2. Gleo AI가 Finder의 기능 목록(App Schema)을 보고 `PICKUP(action="start", memberName="와이프")`를 호출합니다.
3. Finder가 한 번에 처리합니다.
   - 아들의 공유 설정 확인: 항상 허용이면 최신 위치 조회, 일시적 허용이면 아들 폰에 공유 요청을 보내고 수락을 기다림
   - NaviHelper로 아들 위치까지 길 안내 시작
   - 아들 폰에 "아빠가 픽업하러 오고 있어요" 알림과 도착 예정 시간 전송
4. Finder가 결과를 Gleo AI에 돌려주고(Callback), Gleo AI가 "아들 위치로 안내를 시작했고 픽업 알림을 보냈어요"라고 답합니다.

### Gleo에 등록하는 기능 (최대 3개)

| 기능 | 예시 발화 | 동작 |
| --- | --- | --- |
| `PICKUP(action, memberName)` | "플레오스 파인더로 와이프 픽업가줘", "픽업 그만할래", "아들 지금 어디쯤이야?" | 픽업 시작(항상 허용이면 바로 안내, 일시적이면 공유 요청)·종료·남은 거리 답변 |
| `SHARE_LOCATION(targetName, shareType, durationMinutes, untilEndOfToday)` | "박지훈한테 1시간만 위치공유해줘", "강릉 여행 그룹에 2시간만 위치 공유해줘", "강릉 여행 그룹에 지금 목적지 공유해줘", "강릉 여행 그룹에 여기로 모이자고 해줘" | 사람이면 차량끼리 서로 공유, 그룹이면 그룹에 일시적 공유. 30분 단위 최대 24시간, 시간을 말하지 않으면 되물음. shareType이 current_destination이면 지금 내비 목적지를, car_position이면 지금 내 차 위치(모이는 곳)를 그룹에 목적지로 공유 |
| `STOP_LOCATION_SHARING(targetName, category)` | "친구 목록 중에 위치공유 되어있는 것들 모두 꺼줘" | 한 사람·그룹, 또는 가족·친구·그룹·전체 목록에서 내가 켜 둔 공유를 모두 끔 |

Gleo 함수는 최대 3개라 픽업 관련 동작을 `PICKUP` 하나로 묶었습니다. 이름은 운전자가 부르는 호칭(와이프, 남편, 아들)과 계정 이름 모두로 찾습니다. 무전 1단계 메시지 기능은 디벨롭 단계에서 이 중 하나와 합치거나 교체합니다.

### 상황별 응답

| 상황 | 결과 상태 | Gleo AI 응답 예 |
| --- | --- | --- |
| 정상 처리 | success | "아들 위치로 안내를 시작했어요." |
| 일시적 허용이라 아들의 수락이 필요 | success | "아들에게 위치 공유를 요청했어요. 수락하면 바로 안내할게요." |
| 아들이 공유 요청을 거절 | fail | "아들이 지금은 위치 공유를 원하지 않아요." |
| 대상이 불분명 ("애 데리러 가자") | asking | "아들과 딸 중 누구를 픽업할까요?" |
| 상대가 위치 공유를 끔 | fail | "아들이 위치 공유를 꺼 둬서 안내할 수 없어요." |
| 네트워크 오류 | error | "지금은 위치를 가져올 수 없어요." |

### 구현 방식

- `assets/schema.json`에 위 기능을 정의하고, `AndroidManifest.xml`에 기능별 호출을 받을 곳을 등록합니다.
- 길 안내 화면은 기본 내비가 띄우므로, Finder는 화면 없이 처리하는 `service` 방식으로 호출을 받습니다.
- 음성은 Gleo AI가 받고 Finder는 텍스트만 처리해, 마이크를 직접 쓰지 않고도 운전 중 손을 쓰지 않는 조작을 제공합니다.

### 멀티 픽업 음성 추천 [개발 예정 · 검증 필요]

목표는 Gleo AI가 "현재 엄마 → 아들 → 딸 순서인데, 아들 → 엄마 → 딸 순서가 약 8분 더 빠릅니다. 변경하시겠어요?"라고 안내하고, 운전자가 "응, 바꿔줘" 또는 "그대로 가자"로 답하는 것입니다. 다만 지금까지 확인한 Gleo Interface의 범위에는 제약이 있어 아래처럼 설계하고, 확정하지 않은 부분은 Pleos와 확인합니다.

- **앱이 먼저 말을 거는 기능은 확인되지 않았습니다.** 지금 확인한 방식은 운전자가 말하면 Gleo가 앱 기능을 호출하고, 앱이 짧은 시간(에뮬레이터에서 약 20초) 안에 결과를 돌려주는 구조입니다.
- **1안 (운전자가 먼저 요청):** "파인더, 엄마랑 아들이랑 딸 태우고 집에 가자" → Finder가 추천을 계산해 되묻기(asking) 상태로 "아들을 먼저 픽업하면 약 8분 더 빠릅니다. 순서를 변경할까요?"라고 답합니다. 운전자의 답이 다시 Finder 호출(수락/유지)로 이어지는지는 검증이 필요합니다.
- **2안 (대체):** 음성 수락·거절이 안 되면, 정차 중 화면의 추천 팝업으로 고르고, 음성은 안드로이드 음성 합성(TextToSpeech)으로 추천 내용만 읽어 줍니다(차량 앱의 음성 출력 정책 확인 필요).
- **함수 개수:** Gleo 함수는 최대 3개를 이미 모두 쓰고 있습니다. 새 함수를 만들지 않고 기존 `PICKUP`에 여러 명·목적지·수락/유지 항목을 넣는 방식을 후보로 두되, 등록 형식은 검증 후 확정합니다.
- 계산이 응답 시간 안에 끝나지 않으면 "순서를 계산하고 있어요. 화면에서 확인해 주세요"로 먼저 답하고 화면 팝업으로 이어 갑니다.
- 어떤 경우에도 무응답·인식 실패는 기존 순서 유지로 처리합니다.

### 시연 방식

현재 Pleos Connect Emulator(v2.1.0) 문서에는 Gleo AI 테스트 환경이 안내되어 있지 않습니다. 시연에서는 Gleo AI가 보내는 호출 신호(Gleo Action)를 같은 형식으로 재현해, Finder의 길 안내·알림·결과 반환 전 과정을 보여 줍니다. 음성 인식 단계는 시뮬레이션임을 시연에서 밝힙니다.

## 5. 시스템 구성과 활용 API

플레오스 Finder는 차량 앱, 폰 앱, Finder 서버 세 부분으로 구성되고, 차량 기능은 Pleos Connect SDK로 구현합니다.

```
[차량 앱 (Pleos Connect)] ──┐
                            ├── [Finder 서버] ── 같은 그룹 구성원에게만 위치·상태 전달
[폰 앱 (Android)] ──────────┘
```

차량과 폰은 서로 직접 연결되지 않고, 서버가 같은 그룹 구성원에게만 위치를 전달합니다.

| 구성 | 활용 API·기술 | 용도 |
| --- | --- | --- |
| 차량 앱 | [NaviHelper SDK](https://document.pleos.ai/en/api-reference/connect-sdk-pleos/NaviHelper/intro) | `requestRoute`로 상대 위치 목적지 설정, 남은 거리·시간, `getCurrentLocationInfo`로 차량 현재 위치 |
| 차량 앱 | AAOS CarUxRestrictions, distractionOptimized | 운전 중 화면 사용과 제한 |
| 차량 앱 | Gleo Interface (App Schema, Callback) | 음성 명령 |
| 차량·폰 앱 | MapLibre + OpenFreeMap(OpenStreetMap 자료) | 공유된 위치와 경로를 보여주는 무료 지도 (Google 서비스 없이 동작) |
| 차량 앱 (디벨롭) | FusedLocation, SpeechToText, TextToSpeech, Vehicle SDK | 차종별 정밀 위치, 음성 무전, 핸들 버튼 (콘솔에서 아직 Coming Soon) |
| Finder 서버 | Firebase Realtime Database | 계정·연결·그룹, 위치·픽업 상태 실시간 전달 |
| 폰 앱 | Android 위치 서비스, 포그라운드 서비스 | 사람 위치 수집, 요청 알림 |

기본 내비의 경로 모양은 NaviHelper로 받을 수 없어, 지도의 경로선은 차와 기다리는 사람(픽업), 또는 내 위치와 그룹 목적지(목적지 공유)를 잇는 직선으로 표시합니다(실제 내비 경로와 다름). 그룹 목적지는 지도에 깃발로, 같은 목적지로 가는 차량은 마커에 남은 시간을 함께 표시합니다. 같은 경로를 받는 방법은 Pleos와 협의합니다.

**향후 개선:** 현대자동차 내비게이션이 쓰는 지도를 폰 앱에서도 쓸 수 있다면 무료 지도 대신 그 지도로 교체합니다. 차량 화면과 폰 화면이 같은 지도를 보여 주게 되어, 기다리는 사람도 운전자와 같은 화면으로 차가 오는 길을 확인할 수 있습니다. 여기에 내비 경로를 외부 앱과 공유하는 API가 있다면, 근사 경로 대신 차량 내비와 똑같은 경로선과 도착 예정 시간을 폰에 보여 줄 수 있어 더 좋습니다.

Pleos [Vehicle Data API](https://document.pleos.ai/en/api-reference/vehicle-data-api/intro)는 유럽 한정이고 차량이 마지막으로 보낸 위치를 주는 방식이라, 실시간 공유에는 사용하지 않습니다.

### 스마트 멀티 픽업 구성 [개발 예정]

```
[차량 앱] 사람 선택(순서) · 순서 고정 · 최종 목적지
   │
   ├─ [Finder 서버] 사람별 위치 공유 동의·최신 위치 확인 (미승인은 제외)
   │
   ├─ [이동시간 공급원] 차량·각 픽업 지점·목적지 사이 실제 도로 이동시간 (검증 필요)
   │
   ├─ [추천 계산] 고정 순서를 지키는 순서만 비교 → 더 빠를 때만 추천과 절약 시간
   │
   ├─ [운전자 확인] 팝업 / Gleo 음성 → 수락하면 추천 순서, 거절·무응답이면 기존 순서
   │
   ├─ [NaviHelper] 확정 순서를 경유지 경로로 안내, 경유지별 남은 거리·시간 수신
   │
   └─ [Finder 서버 → 폰 앱] 사람별 본인 차례까지 남은 km·분·예상 픽업 시각
```

**추천 계산:** 1차 목표는 차량 전체 예상 주행시간 최소화이고, 운전자가 고정한 순서는 반드시 지킵니다. 2~6명은 출발지와 최종 목적지를 고정한 방문 순서를 모두 비교(6명이면 720가지)해도 충분해 별도 학습 AI나 시뮬레이션 플랫폼을 쓰지 않습니다. 직선거리로는 비교하지 않고 실제 도로 이동시간만 씁니다. 인원·차량·시간 제약이 커지는 단계에서 NVIDIA cuOpt 같은 경로 최적화 엔진을 **[후속 검토]**합니다(cuOpt는 최적화 계산 엔진이며 학습형 AI나 도로 데이터 공급원이 아닙니다).

**NaviHelper 3.0.5 SDK 확인 결과와 검증 필요 사항** (SDK 클래스 정의로 확인, 실제 동작은 미검증):

| 항목 | SDK에서 확인한 것 | 기획 반영과 검증 필요 |
| --- | --- | --- |
| 경유지 안내 | `requestRouteWithWaypoints(RouteWithWaypointsRequest(목적지, 경유지 목록))`, `addWaypoint`·`removeWaypoint`. 경유지 순번 상수는 `FIRST`·`SECOND`뿐 | 한 경로에 경유지 2개까지로 보임. 3명 이상이면 구간을 나눠(경유지 2곳 + 다음 픽업을 목적지로) 안내하고 도착할 때마다 다음 구간 요청. 실제 개수·갱신 제약 검증 필요 |
| 경유지별 남은 거리·시간 | `onDrivingInfo`의 경유지별 거리·시간 목록, `onWayPointInfo`(경유지별 남은 거리·시간), `onWayPointArrived` | 내비 경로 기준이라 탑승자별 km·분에 쓸 수 있음. 값이 현재 위치부터의 누적값인지 검증 필요. 구간을 나눈 경우 다음 구간은 이동시간 공급원 값으로 보완 |
| 지점 간 이동시간 | `requestTrip(목적지)` → `onTripInfo`(거리, 예상 시간). 출발지는 현재 차 위치뿐 | 차 → 각 사람은 얻을 수 있으나 사람 ↔ 사람 구간은 얻을 수 없음. 임의 지점 간 이동시간 API 제공 여부는 Pleos 확인 필요 |
| 외부 라우팅 대안 | - | NaviHelper로 부족하면 외부 경로 API(예: Google Routes) 또는 OSM 기반 엔진(Valhalla 등 자체 운영) 검토. 약관·지역 범위·비용과 위치 정보가 외부로 나가는 개인정보 영향 검토 필요 |
| 대체 동작 | - | 이동시간을 얻지 못하면 추천 없이 운전자가 고른 순서로 안내(단일 픽업·수동 순서로 안전하게 대체) |

**저장 데이터:** 서버에는 멀티 픽업의 확정 순서, 사람별 진행 상태와 최신 남은 거리·시간만 두고 이동 기록은 남기지 않습니다(7장 최소 저장 원칙).

## 6. 화면 구성

차량 화면은 운전 중 한 번 터치로 끝나는 구조로, 폰 화면은 그룹 관리와 상황 확인 중심으로 구성합니다. 그룹 구성원 위치를 기본 내비 지도에 표시할지, Finder 앱 자체 지도에 표시할지는 Pleos 협의 후 확정합니다(10장).

### 차량 화면

| 영역 | 구성 | 운전 중 |
| --- | --- | --- |
| 오른쪽 위 프로필 | 동그란 프로필과 이름, 눌러서 운전자 계정 전환 | 정차 중에만 |
| 픽업 줄 | 픽업 중일 때만 맨 위에 얇게 표시: 상대 이름·상태, 남은 거리·시간, 픽업 종료. 화면이 나뉘어도 한 칸 그대로 | 내비 화면 유지, 전체 화면 팝업 없음 |
| 목록 (기본 한 칸) | 가족 → 친구 → 그룹 패널. 이름 옆 사람·차량 아이콘과 공유 상태 점 | 항목 누르기 허용 |
| 항목 펼침 | 사람은 '픽업', 차량은 '위치 공유'(오늘 하루만 / 시간 설정) 버튼, 누르면 바로 시작 | 허용 (한 번 터치) |
| 그룹 상세 (두 칸) | 그룹을 누르면 목록 \| 그룹 상세로 부드럽게 나뉘고, 닫기를 누르면 한 칸으로 돌아옴. 구성원, 내 공유 설정(항상/일시적 +30분/끄기), 연락처에서 초대 | 초대·그룹 만들기는 정차 중에만 |
| 멀티 픽업 구성 **[개발 예정]** | 가족·친구 목록에서 여러 명을 순서대로 선택(번호 표시), 사람별 순서 고정 토글, 최종 목적지 선택, 사람별 공유 동의 상태 | 정차 중에만 (주행 중에는 Gleo 음성) |
| 추천 확인 팝업 **[개발 예정]** | "현재 순서보다 ○○ 순서가 약 N분 빠릅니다" + [추천 순서로 변경] [기존 순서 유지] | 짧은 팝업 한 번, 무응답이면 기존 순서로 진행 |
| 멀티 픽업 진행 줄 **[개발 예정]** | 기존 픽업 줄을 확장: 현재 픽업 대상, 다음 순서, 사람별 상태(완료·이동 중·대기·미승인) | 내비 화면 유지 |

## 7. 운전 안전과 개인정보 보호

플레오스 Finder는 Pleos의 운전 중 제한 기준을 처음부터 따르고, 위치는 동의한 사람에게 필요한 동안만 공개합니다.

### 운전 안전

- 플랫폼의 운전 상태(CarUxRestrictions)에 따라 화면과 기능을 자동으로 줄입니다. 출품본은 주행 중(D단)에 초대·그룹 만들기·이름 변경·운전자 전환 버튼을 흐리게 하고, 누르면 "주행 중에는 사용할 수 없어요. 정차한 뒤 이용해 주세요."로 안내합니다(픽업·위치 공유·목적지 안내 같은 한 번 터치 동작은 주행 중에도 사용).
- 메뉴는 3단계 이내로 두고, 긴 목록 스크롤과 애니메이션, 광고는 넣지 않습니다.
- 운전 중에는 한 번 터치와 음성 입력만 사용하고, 전체 화면 팝업은 띄우지 않습니다.
- 그룹 만들기와 초대 같은 입력 작업은 폰이나 정차 중 차량 화면에서만 합니다.

### 스마트 멀티 픽업의 안전·예외 처리 [개발 예정]

- 사람 선택, 목적지 검색, 순서 편집은 정차 중에만 하고, 주행 중에는 Gleo 음성과 짧은 확인만 씁니다.
- 경로 변경과 순서 변경은 **운전자가 명시적으로 수락했을 때만** 적용합니다. 거절·무응답·음성 인식 실패는 기존 순서 유지로 처리하는 정상 동작입니다.
- 위치 공유를 승인하기 전에는 그 사람의 실제 위치를 추천 계산에 쓰지 않고, 경로에 넣을지 화면에 분명히 표시합니다.
- 위치가 오래됐거나 정확도가 낮으면 경고하고, 공유 취소·시간 만료 시 그 사람을 대기 상태로 바꿔 운전자에게 알립니다.
- 픽업 지점은 상대의 현재 위치이며, 1차 버전은 안전한 승하차 지점을 보장하거나 추천한다고 표현하지 않습니다.
- 경로 API 실패나 네트워크 단절 시에는 추천 없이 운전자가 고른 순서 또는 단일 픽업으로 안전하게 이어 갑니다.

### 개인정보 보호

| 원칙 | 설계 |
| --- | --- |
| 동의 기반 | 초대를 수락하고 공유를 허용한 상대에게만 공개, 허용 방식은 상대별로 선택 |
| 기간 제한 | 일시적 허용은 픽업이 완료되거나 취소되면 공유가 자동 종료 |
| 즉시 중지 | 언제든 버튼 하나로 내 위치 공유 중지 |
| 최소 저장 | 서버에는 최신 위치만 보관하고 이동 기록은 저장하지 않음 (멀티 픽업도 확정 순서·진행 상태·최신 남은 거리·시간만) |
| 외부 전송 [개발 예정] | 멀티 픽업에 외부 경로 API를 쓰게 되면 보내는 위치 범위를 최소화하고 약관·보관 정책을 확인한 뒤 적용 |
| 암호화 | 위치 데이터는 HTTPS로 전송하고 암호화해 보관 |
| 표시 | 내 위치가 공유 중일 때 폰과 차량 화면에 항상 표시 |

## 8. 차별성

플레오스 Finder의 차별점은 위치 공유가 차량 내비의 길 안내와 바로 이어진다는 것입니다. 운전자는 폰을 만지지 않고, 상대 위치를 다시 검색할 필요도 없습니다. 다음 단계에서는 단순 위치 공유를 넘어, 동의 기반의 단일·다중 픽업과 최종 목적지까지의 순서 추천으로 넓힙니다.

| 비교 항목 | 폰 중심 위치 공유 앱 | 플레오스 Finder |
| --- | --- | --- |
| 운전자의 확인 방법 | 폰 화면 | 차량 화면 |
| 길 안내 | 위치를 보고 내비에 다시 입력 | 상대 위치로 자동 길 안내, 움직이면 자동 갱신 |
| 공유 대상 | 사람(폰) | 사람과 차량 모두 |
| 프라이버시 | 상시 공유 중심 | 상대별로 항상 허용·일시적 허용 선택, 일시적 허용은 픽업이 끝나면 자동 종료 |
| 여러 명 픽업 | 순서를 운전자가 직접 판단, 각자에게 연락 | [개발 예정] 운전자가 정한 순서를 기본으로 안내하고 더 빠른 순서는 선택적 추천(순서 고정 가능), 탑승자별 남은 거리·시간·예상 픽업 시각 |
| 운전 중 소통 | 전화나 메신저 | 차량 무전 (디벨롭 단계) |

## 9. 사업화와 확장 계획

가족용으로 사용자를 모으고, 업무용 그룹 기능으로 수익을 내는 구조입니다.

| 단계 | 대상 | 내용 |
| --- | --- | --- |
| 1. 가족 | 개인 | 가족 그룹과 픽업 모드를 기본 기능으로 제공, 이어서 스마트 멀티 픽업(등하교·학원 픽업) |
| 2. 친구·모임 | 개인 | 차량 그룹, 여행 동행 차량 위치 공유 |
| 3. 업무용 | 촬영팀, 행사 운영사, 소규모 차량 운영 팀 | 프로젝트 그룹, 차량 무전, 여러 차량 현황 보기 |

**확장 방향**

- 현대·기아·제네시스의 Pleos Connect 탑재 차종이 늘어날수록 차량 간 공유 대상도 함께 늘어납니다.
- 차량이 한 대만 있어도 나머지 구성원은 폰 앱으로 참여할 수 있어 초기 확산이 쉽습니다.
- 후속으로 학원 차량, 단체 이동 등 픽업이 많은 분야로 넓힐 수 있습니다.

## 10. 개발 계획과 협의 필요 사항

개발은 Pleos Connect Emulator에서 픽업 모드를 먼저 완성하고, 그룹 공유와 무전 순서로 넓힙니다.

1. **완료:** 픽업 모드, 가족 초대와 항상·일시적 허용, Pleos 디자인 시스템 UI, Gleo AI 음성 연동 (에뮬레이터 검증)
2. **완료 — 계정·연결 구조:** 사람·차량·운전자 모델, 프로필 전환, 차량·폰 앱 가족·친구·그룹 패널과 아이콘, 눌러서 픽업, 두 앱 공통 앱 아이콘
3. **완료 — 그룹:** 만들기·이름 변경, 연락처 초대·수락, 그룹별 허용(일시적 = 30분 단위), 운전자 기준 차량 위치 공유, 폰 앱에서 차량 위치 보기
4. **완료 — 지도:** 차량·폰 앱 공용 지도(MapLibre + OpenFreeMap), 사람·차량 마커, 픽업 중 차와 상대를 잇는 선
5. **완료 — 목적지 공유와 운전 안전:** 그룹 목적지 공유와 차량별 도착 예정, 지도 목적지 표시, 운전 중 화면 제한, Gleo 음성 목적지 공유
6. **시연 준비:** 기획서·DOCX, 시연 영상, 보안 규칙
7. **개발 예정 — 스마트 멀티 픽업**
   - 1단계 **[구현]**: 여러 명 순서 선택·순서 고정·최종 목적지·동의 확인, 고른 순서 그대로 경유지 안내, 탑승자별 남은 거리·시간·예상 픽업 시각 (에뮬레이터 확인)
   - 2단계: 실제 도로 이동시간 확보(공급원 검증 후) → 고정 조건을 지키는 선택적 순서 추천 → 추천 팝업과 수락·거절
   - 3단계: Gleo AI 음성 추천과 음성 수락·거절 (Gleo 지원 범위 검증 후, 안 되면 화면 팝업 + 음성 합성 안내)
   - 후속 검토: 자동 재최적화 제안, 대기·탑승 시간 고려, 여러 차량 배정(cuOpt 검토), 승차 지점 추천
8. **디벨롭:** 음성 메시지 → 핸들 버튼 → 실시간 무전
